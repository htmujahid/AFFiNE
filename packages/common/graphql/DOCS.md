## 1. What this package contains

```
src/
  fetcher.ts    — gqlFetcherFactory + request plumbing
  graphql.ts    — GraphQLQuery interface + all operation definitions
  schema.ts     — All generated TypeScript types from the GraphQL schema (3000+ lines)
  index.ts      — re-exports
```

Everything in `schema.ts` and `graphql.ts` is auto-generated by GraphQL Code Generator from `packages/backend/server/schema.gql`. **Do not edit these files manually.** Run `yarn affine init` to regenerate.

## 2. `gqlFetcherFactory` — the main entry point

**File:** `src/fetcher.ts`

Creates a typed fetch function bound to a specific GraphQL endpoint:

```ts
import { gqlFetcherFactory } from '@affine/graphql';

const gql = gqlFetcherFactory('https://app.affine.pro/graphql');
```

The returned `gql` function has the signature:

```ts
function gql<Q extends GraphQLQuery>(query: Q, variables: QueryVariables<Q>, options?: RequestOptions): Promise<QueryResponse<Q>>;
```

Type parameters are inferred automatically from the `query` argument — you never need to write them explicitly.

### `RequestOptions`

```ts
interface RequestOptions {
  signal?: AbortSignal; // cancellation
  timeout?: number; // ms, default unlimited
  context?: Record<string, unknown>; // passed through to custom fetcher
}
```

### Custom fetcher

Pass a second argument to use your own `fetch` implementation:

```ts
const gql = gqlFetcherFactory('/graphql', async (query, vars, options) => {
  const res = await myAuthenticatedFetch('/graphql', {
    method: 'POST',
    body: JSON.stringify({ query, variables: vars }),
    signal: options?.signal,
  });
  return res.json();
});
```

## 3. Making a query or mutation

All operations are pre-defined in `src/graphql.ts`. Import the operation object and pass it to `gql`:

```ts
import { gql, getCurrentUserQuery, createWorkspaceMutation, deleteWorkspaceMutation } from '@affine/graphql';

// Query — variables inferred as { /* empty */ }
const { currentUser } = await gql(getCurrentUserQuery, {});

// Mutation — variables typed from schema
const { createWorkspace } = await gql(createWorkspaceMutation, {
  init: workspaceBinaryBuffer, // Upload scalar
});

// TypeScript errors if you pass wrong variables
await gql(createWorkspaceMutation, { wrongField: 'value' }); // TS error
```

## 4. File uploads

Operations that include an `Upload` scalar variable are automatically sent as `multipart/form-data` instead of JSON, following the [GraphQL multipart request spec](https://github.com/jaydenseric/graphql-multipart-request-spec).

This is handled transparently by `transformToForm()` inside `fetcher.ts` — you just pass a `File` or `Blob` as the variable value:

```ts
const file = new File([bytes], 'avatar.png', { type: 'image/png' });

await gql(uploadAvatarMutation, { avatar: file });
// Sent as multipart/form-data automatically
```

`filterEmptyValue()` strips `null`/`undefined` variable fields before sending, so optional variables don't have to be explicitly omitted.

## 5. Error handling

GraphQL errors from the server come back as `GraphQLError` instances (from `@affine/error`):

```ts
import { UserFriendlyError, GraphQLError } from '@affine/error';

try {
  await gql(someQuery, {});
} catch (e) {
  const err = UserFriendlyError.fromAny(e);

  if (err.is('WORKSPACE_NOT_FOUND')) {
    // typed check
  }

  if (err.isNetworkError()) {
    // offline / CORS / DNS failure
  }

  console.log(err.message); // user-readable message from server
}
```

The `fetcher.ts` maps raw `ExecutionResult.errors[]` → throws a single `GraphQLError` with `extensions` populated from the first error's `extensions.code`.

## 6. Generated types

All GraphQL schema types are in `src/schema.ts`. Key types you'll use regularly:

```ts
// User
type UserType = {
  id: string;
  name: string;
  email: string;
  avatarUrl: string | null;
  emailVerified: boolean;
  hasPassword: boolean | null;
  // ... features, quota, subscriptions
};

// Workspace
type WorkspaceType = {
  id: string;
  public: boolean;
  team: boolean;
  // ... member count, feature flags
};

// Copilot
type CopilotHistories = {
  sessionId: string;
  tokens: number;
  messages: ChatMessage[];
  // ...
};

// Subscription
type UserSubscription = {
  plan: SubscriptionPlan;
  status: SubscriptionStatus;
  start: string; // Date ISO string
  end: string | null;
  // ...
};
```

### Scalar types

| Scalar     | TypeScript type           |
| ---------- | ------------------------- |
| `DateTime` | `string` (ISO 8601)       |
| `JSON`     | `Record<string, unknown>` |
| `Upload`   | `File \| Blob`            |
| `SafeInt`  | `number`                  |

## 7. Adding a new operation

1. Add the operation to `packages/backend/server/src/schema.gql` (or the appropriate resolver).
2. Add the `.graphql` file in `packages/common/graphql/src/graphql/` (or inline in `graphql.ts`).
3. Run `yarn affine init` — this regenerates `schema.ts` and `graphql.ts`.
4. The new operation is immediately available as a typed import.

**Never write raw `fetch('/graphql', ...)` calls in application code.** Always use `gql(operationObject, variables)` so the types stay in sync with the server schema.
